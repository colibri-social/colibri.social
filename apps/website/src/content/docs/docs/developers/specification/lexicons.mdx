Colibri's lexicons define its wire format. The AppView validates against them,
handler types are generated from them, and a change to one is a protocol
change.

They are authored in the AppView repository and published as
[`@colibri-social/lexicons`](https://www.npmjs.com/package/@colibri-social/lexicons),
which ships the raw JSON alongside generated TypeScript. Import those types in
your own code. The definitions rendered on this page are generated from that
package.

## Reading these

Two properties of [ATproto spaces](/docs/developers/architecture/spaces) shape most of
what you see below.

**A space type is a lexicon.** Eight of the documents here have a `main`
definition of type `space`. Each lists the record collections its space may hold
and carries a `title`, the name an OAuth consent screen shows.

**A record is addressed by author as well as key.** Record keys are unique per
repository, and a space aggregates many repositories, so a bare key is
ambiguous. Message parents and reaction targets carry `{ did, rkey }`. Role and
channel references stay bare keys, because those are only ever written by the
Space itself.
