Embedded mode renders a singular Colibri community inside a page you control. It is the same client that runs at colibri.social, with the parts that only make sense in a standalone app taken out.

## What's included

The embed shows the community's channels, its messages, its member list, and voice channels. Admins who have permission can still open community settings and moderate. Users can still edit their own profile and status.

It does not include:

- The community switcher
- Sign-in (See [Authentication](#authentication) below)
- Invites
- Community creation, the welcome screen, account deletion, the updater and the title bar

Important limits worth knowing about:

- It is currently dark mode only, the `colorScheme` option is a placeholder

## Authentication

This is the one part you cannot skip or work around, so it comes first.

The embed does not sign users in. You hand it an already-authenticated `Agent` from `@atproto/api`, created on your own origin.

Your origin needs three things:

<Steps>

1. **An OAuth client metadata document**, served from your own origin at a stable URL. Its `client_id` must equal its own URL, and its `redirect_uris` must be on your origin.

2. **The scopes Colibri needs.** The embed checks these at startup and blocks with an explanation if they are missing. We recommend you only "upgrade" the OAuth session when a user loads the chat. For the default AppView (`api.colibri.social`):

   ```json title="https://example.com/oauth-client-metadata.json"
   {
     "client_id": "https://example.com/oauth-client-metadata.json",
     "client_name": "Example",
     "client_uri": "https://example.com",
     "redirect_uris": ["https://example.com/oauth/callback"],
     "scope": "atproto blob:*/* rpc:app.bsky.actor.getProfile?aud=* rpc:com.atproto.identity.resolveDid?aud=* rpc:social.colibri.voice.signal?aud=* rpc:social.colibri.voice.moderate?aud=* include:social.colibri.permissionAccount?aud=did:web:api.colibri.social#colibri_appview include:social.colibri.permissionCommunity?aud=did:web:api.colibri.social#colibri_appview include:social.colibri.permissionMessaging?aud=did:web:api.colibri.social#colibri_appview include:social.colibri.permissionNotification?aud=did:web:api.colibri.social#colibri_appview include:social.colibri.permissionPush?aud=did:web:api.colibri.social#colibri_notif",
     "grant_types": ["authorization_code", "refresh_token"],
     "response_types": ["code"],
     "application_type": "web",
     "token_endpoint_auth_method": "none",
     "dpop_bound_access_tokens": true
   }
   ```

   Our own documents are generated by [`oauth-client-metadata.json.ts`](https://github.com/colibri-social/colibri.social/blob/main/apps/website/src/pages/oauth-client-metadata.json.ts) and the per-AppView [`c/[appview]/oauth-client-metadata.json.ts`](https://github.com/colibri-social/colibri.social/blob/main/apps/website/src/pages/c/%5Bappview%5D/oauth-client-metadata.json.ts). Use them as the reference shape.

   :::caution
   The `include:` permission sets pin an audience. If you point the embed at a self-hosted AppView with `appViewUrl`, every `aud=` above has to name that AppView's `did:web` instead, or the authorization server will reject the request.
   :::

3. **A completed sign-in**, producing the `Agent`. `@atproto/oauth-client-browser` handles the flow:

   ```ts
   import { Agent } from "@atproto/api";
   import { BrowserOAuthClient } from "@atproto/oauth-client-browser";

   const oauth = await BrowserOAuthClient.load({
     clientId: "https://example.com/oauth-client-metadata.json",
     handleResolver: "https://api.colibri.social",
   });

   const result = await oauth.init();
   const agent = result ? new Agent(result.session) : undefined;
   ```

</Steps>

If you have no session yet, do not mount the embed. `mountColibri` throws without a usable agent.

## Installing

```bash
npm install @colibri-social/client
```

Import the **embed** stylesheet, not `index.css`:

```ts
import "@colibri-social/client/embed.css";
```

## Mounting

The public surface is one imperative function, so it works the same from any framework.

<Tabs>
  <TabItem label="Nuxt / Vue">

Mount from `onMounted` and tear down in `onUnmounted`. Wrap the component in `<ClientOnly>` (or name the file `*.client.vue`) so it never runs during SSR.

```vue title="components/CommunityChat.client.vue"
<script setup lang="ts">
import { mountColibri, type EmbedHandle } from "@colibri-social/client/embed";
import "@colibri-social/client/embed.css";

const props = defineProps<{ agent: Agent }>();
const container = ref<HTMLElement>();
let handle: EmbedHandle | undefined;

onMounted(() => {
  if (!container.value) return;
  handle = mountColibri(container.value, {
    agent: props.agent,
    community: "did:plc:example",
    brand: "#eab308",
    onEvent: (event) => console.log(event.kind, event),
  });
});

onUnmounted(() => handle?.unmount());
</script>

<template>
  <div ref="container" style="height: 640px" />
</template>
```

  </TabItem>
  <TabItem label="Plain JS">

```ts
import { mountColibri } from "@colibri-social/client/embed";
import "@colibri-social/client/embed.css";

const handle = mountColibri(document.getElementById("chat")!, {
```

  </TabItem>
  <TabItem label="React">

```tsx
import { useEffect, useRef } from "react";
import { mountColibri } from "@colibri-social/client/embed";
import "@colibri-social/client/embed.css";

export const CommunityChat = ({ agent }: { agent: Agent }) => {
  const ref = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (!ref.current) return;
    const handle = mountColibri(ref.current, {
      agent,
      community: "did:plc:example",
    });
    return () => handle.unmount();
  }, [agent]);

  return <div ref={ref} style={{ height: 640 }} />;
};
```

  </TabItem>

**Give the container a height.** The embed fills the element you hand it. A container with no height renders nothing visible.

`community` accepts a full `at://` URI.

The embed uses an in-memory router. It never touches your URL or your history, and it will not fight your router. Channel changes are reported as `navigation` events if you want to mirror them yourself, and `handle.navigate({ channel })` drives it the other way.

## Theming

Every colour is a CSS custom property under the `--colibri-embed-` prefix. Those names are the public surface, everything behind them is private and may be renamed.

The quickest route is one brand colour:

```ts
mountColibri(el, { agent, community, brand: "#eab308" });
```

That derives `primary`, `primary-hover`, `primary-foreground`, `ring` and the matching sidebar tokens, choosing a foreground that clears WCAG AA against your colour. Mid-tone yellows, ambers and limes cannot carry legible text at any foreground: the embed picks the closest one and emits an `error` event with code `EmbedLowContrastBrand`.

For full control, pass tokens directly, or set the same variables in your own CSS:

```ts
mountColibri(el, {
  agent,
  community,
  theme: {
    background: "#09090b",
    foreground: "#fafafa",
    card: "#18181b",
    primary: "#eab308",
    "primary-foreground": "#18181b",
    "muted-foreground": "#a1a1aa",
    border: "#27272a",
    radius: "0.5rem",
    "font-sans": '"Geist Variable", system-ui, sans-serif',
  },
});
```

### Corners

`radius` is the base and the whole `rounded-*` scale derives from it, so one value reshapes every surface:

```ts
mountColibri(el, { agent, community, theme: { radius: "0px" } });
```

Each step is also its own token (`radius-sm` through `radius-4xl`) if you want to pin one, say square inputs inside rounded cards:

```ts
handle.setTheme({ radius: "1rem", "radius-md": "0px" });
```

Avatars and presence dots use `rounded-full` and stay circular at any setting.

```css
.colibri-embed {
  --colibri-embed-primary: #eab308;
  --colibri-embed-background: #09090b;
}
```

`handle.setTheme(partial)` rewrites tokens live, so an accent picker in your own settings can drive the embed without remounting it. See the [reference](/docs/embedding/reference) for the full token list.

## Watching what happens

Every read, write and realtime event can be observed.

```ts
mountColibri(el, {
  agent,
  community,
  onEvent: (event) => {
    if (event.kind === "record.created") {
      console.log("wrote", event.collection, event.uri);
    }
  },
});
```

`handle.on(listener)` adds listeners later and returns an unsubscribe function. Every payload is documented in the [reference](/docs/embedding/reference).

## Troubleshooting

**Menus, tooltips and dialogs render unstyled.** They are portalled, and the embed mounts them inside its own root so the scoped styles reach them. Seeing this means `embed.css` did not load at all. Check the import.

**Your page's typography, background or link colours changed.** You imported `index.css` instead of `embed.css`.

**A panel says the chat needs more permissions.** Your client metadata is missing scopes from the list above. The embed also emits `scopes.missing` with the specific permission sets. Only you can fix this, which is why the embed does not try.

**Nothing renders and the console shows a thrown `EmbedConfigInvalid`.** Either `agent` is missing or not signed in, or `community` is not a community identifier.

**Voice channels do not connect.** The embed needs HTTPS and microphone permission from your page. A `Permissions-Policy` header that blocks `microphone` will stop it.

**Two embeds on one page share preferences.** Storage keys are namespaced per embed via `storagePrefix`, but the namespace is process-wide: the first embed to mount wins and the second logs a warning. Two embeds of the same community are fine. Two different communities on one page will share user preferences.
